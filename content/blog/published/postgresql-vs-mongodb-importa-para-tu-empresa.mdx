De todas las decisiones técnicas que enfrenta un proyecto de software, la elección de la base de datos es una de las que menos debería preocupar a un empresario. No porque no sea importante, sino porque es una decisión que el equipo técnico está mejor calificado para tomar que la dirección del negocio.

Sin embargo, es útil entender la diferencia entre bases de datos SQL (como PostgreSQL) y NoSQL (como MongoDB) porque de vez en cuando un desarrollador dirá "necesitamos MongoDB porque los datos no son relacionales" y conviene saber qué significa eso y si realmente aplica.

## La diferencia fundamental

Las bases de datos SQL —también llamadas relacionales— organizan la información en tablas con filas y columnas, como una planilla de Excel. Cada tabla representa una entidad (clientes, productos, pedidos) y las relaciones entre tablas se definen mediante identificadores compartidos.

PostgreSQL es una base de datos SQL de código abierto, muy madura y confiable. Es la base de datos más usada en proyectos nuevos y tiene una reputación sólida por su estabilidad, su cumplimiento de estándares y sus funcionalidades avanzadas.

Las bases de datos NoSQL —como MongoDB— organizan la información de forma más flexible. En lugar de tablas rígidas, usan documentos (similar a archivos JSON) que pueden tener estructuras diferentes entre sí. Esto permite guardar información sin tener que definir previamente la estructura exacta.

## ¿Cuándo elegir PostgreSQL?

PostgreSQL es la opción correcta para la gran mayoría de los proyectos. Es la base de datos más versátil y confiable, y es la que la mayoría de los desarrolladores conoce mejor.

Elige PostgreSQL cuando:

- Los datos tienen relaciones claras y definidas (clientes que hacen pedidos, productos que pertenecen a categorías).
- Necesitas garantías de integridad: que los datos sean consistentes, que no haya información huérfana o duplicada.
- Vas a hacer consultas complejas que combinen datos de múltiples tablas.
- Necesitas soporte transaccional: operaciones donde varias cosas tienen que ocurrir juntas o ninguna debe ocurrir (por ejemplo, transferir dinero de una cuenta a otra).
- No tienes una razón específica para usar otra base de datos.

En la práctica, PostgreSQL es la respuesta correcta en al menos el 80% de los proyectos. Es la base de datos más equilibrada y la que menos sorpresas da a largo plazo.

## ¿Cuándo elegir MongoDB?

MongoDB es útil en escenarios donde la estructura de los datos es variable o no está definida de antemano. Es especialmente popular en proyectos que manejan datos semiestructurados o donde el esquema de datos cambia frecuentemente.

Elige MongoDB cuando:

- Los documentos que guardas tienen estructuras muy diferentes entre sí y no encajan bien en tablas fijas.
- El esquema de datos cambia constantemente y no quieres tener que modificar la estructura de la base de datos cada vez.
- Necesitas escalar horizontalmente de forma muy agresiva (distribuir los datos entre muchos servidores).
- Trabajas con datos en formato JSON de forma nativa y la flexibilidad del documento es más importante que la consistencia relacional.

Casos típicos donde MongoDB brilla: catálogos de productos con atributos muy variables, sistemas de logging y eventos, aplicaciones que manejan datos de redes sociales o feeds de actividad, prototipos donde el esquema aún no está definido.

<Callout variant="info" title="La verdad incómoda: para la mayoría de los proyectos no importa">
  El 90% de los proyectos empresariales funcionaría perfectamente con cualquiera de las dos opciones. La diferencia entre PostgreSQL y MongoDB solo se vuelve relevante cuando el proyecto tiene requisitos muy específicos de escalado horizontal (MongoDB gana) o de integridad transaccional compleja (PostgreSQL gana). Para el resto, la decisión depende más de la experiencia del equipo que de las necesidades del proyecto.
</Callout>

## Los mitos más comunes

**"MongoDB es más rápido."** Depende. Para operaciones simples sobre documentos individuales, MongoDB puede ser más rápido. Para consultas que cruzan múltiples entidades, PostgreSQL suele ganar. La velocidad depende del tipo de operación, no del tipo de base de datos.

**"PostgreSQL no escala."** Falso. PostgreSQL escala verticalmente muy bien (servidores más potentes) y también tiene opciones de escalado horizontal, aunque requieren más configuración. Para la mayoría de las empresas, PostgreSQL escala más que suficiente.

**"MongoDB es más moderno."** Las bases de datos SQL existen desde los años 70, y las NoSQL desde los 2000. La "modernidad" no es un criterio de selección relevante. Ambas tecnologías son maduras y ampliamente usadas.

**"NoSQL es mejor para aplicaciones web."** La mayoría de las aplicaciones web más grandes del mundo usan bases de datos SQL. La elección no tiene relación con el tipo de aplicación.

**"MongoDB no necesita esquema."** Si bien MongoDB no exige un esquema fijo, en la práctica las aplicaciones bien diseñadas terminan definiendo una estructura consistente para los documentos. La flexibilidad inicial puede convertirse en un problema si no se gestiona con disciplina, porque documentos con estructuras muy diferentes dentro de una misma colección dificultan las consultas y el mantenimiento del código.

## La decisión práctica

Si estás contratando el desarrollo de un software, deja que tu equipo técnico elija la base de datos. Las preguntas que deberías hacer no son "¿por qué PostgreSQL?" sino "¿qué experiencia tiene el equipo con esa base de datos?" y "¿qué pasa si necesitamos cambiar en el futuro?"

La mejor base de datos es la que tu equipo conoce mejor. Una base de datos técnicamente superior pero que nadie en el equipo sabe administrar va a generar más problemas que beneficios.
